# お問い合わせフォーム送信完了ページ 実装設計書

- 作成日: 2026-06-08
- ステータス: 実装完了
- 対象領域: 公開サイト / お問い合わせフォーム / 送信完了導線
- 対象画面: `contact.html` / `contact-complete.html`

## 背景

現在のお問い合わせフォームは、Firestore `contactSubmissions` への保存が成功した後、`contact.html` のフォーム内に以下の完了メッセージを表示している。

```text
送信ありがとうございました。受付完了メールを登録いただいたメールアドレスへお送りします。
```

スマートフォン表示では、フォーム下部のステータス表示として完了文言が出るため、送信完了後も同じフォーム画面に留まる。ユーザーに「送信が完了した」ことをより明確に伝えるため、送信成功後は独立した完了ページへ遷移させる。

## 要望

- お問い合わせフォーム送信後に、同一画面内の完了メッセージ表示で終わらせない。
- 「フォームの送信が完了しました」という趣旨の独立ページを作成する。
- フォーム送信が正常に完了した後、その完了ページへ自動遷移する。
- 完了ページには、送信が完了したことと、受付完了メールが登録メールアドレスに送られる旨を記載する。

## 既存方針との整合

### サイト構成

`SITE_STRUCTURE.md` では、`contact.html` を参加希望者や問い合わせを受け付けるページとして定義している。今回追加する完了ページは、フォーム送信後だけに到達する補助ページとして扱う。

実装完了後、`SITE_STRUCTURE.md` の「参加・お問い合わせ」に、送信成功後の遷移先として `contact-complete.html` を追記する。

### デザイン

`DESIGN_GUIDELINES.md` のフォーム・ボタン方針に合わせる。

- 完了ページは既存公開ページと同じヘッダー、フッター直前SNS導線を使う。
- 完了メッセージは白背景カードまたは既存のフォームカードに近い見た目で、`var(--radius-lg)` と控えめな影を使う。
- 主要ボタンは `.button--pill-large.button--green` を使う。
- 副導線は白背景のアウトラインボタンを使う。

### 文言

`CONTENT_GUIDELINES.md` の自動返信メール方針と矛盾しないよう、完了ページでは以下を伝える。

- フォーム送信が完了したこと。
- 登録されたメールアドレスへ受付完了メールを送ること。
- 返信目安は自動返信メール側の方針に合わせて「3営業日以内」を基準にする。
- 送信後に追加連絡が必要な場合は公式Instagram DMも使えること。

## 実装方針

### 1. 完了ページを新規作成する

新規ファイル:

```text
contact-complete.html
```

ページの主な構成:

- 共通ヘッダー
- 完了メッセージセクション
- 補足文
- トップページへ戻るボタン
- 公式Instagramへの導線
- 共通のフッター直前SNS導線

想定タイトル:

```text
フォームの送信が完了しました | Molkkynist
```

想定見出し:

```text
フォームの送信が完了しました
```

想定本文:

```text
お問い合わせありがとうございます。
ご入力いただいた内容を受け付けました。
受付完了メールを、登録いただいたメールアドレスへ自動でお送りします。
内容を確認のうえ、通常3営業日以内を目安にご連絡します。
```

補足:

```text
追加で伝えたいことがある場合や、メールが届かない場合は、公式InstagramのDMからもご連絡いただけます。
```

### 2. フォーム送信成功時の挙動を変更する

対象ファイル:

```text
js/contact-form.js
```

現在は `addDoc()` 成功後にフォームをリセットし、`showStatus()` で成功メッセージを表示している。

変更後は、Firestore 保存成功後に `contact-complete.html` へ遷移する。

想定処理:

```js
window.location.href = "contact-complete.html";
```

方針:

- Firestore への保存が成功した場合のみ遷移する。
- 保存失敗時は現行どおり `contact.html` 内にエラーメッセージを表示する。
- Firebase 未設定時のInstagram DM案内は現行どおり維持する。
- 送信中表示は現行どおり維持する。
- 遷移直前の `formEl.reset()` は不要だが、ブラウザバック時の見え方を考慮して残すかどうかは実装時に確認する。

### 3. フォーム内の成功メッセージの役割を変更する

送信成功後は完了ページへ遷移するため、通常時にユーザーがフォーム内の成功メッセージを見ることはなくなる。

ただし、以下の理由からステータス表示要素自体は残す。

- 送信中表示に使うため。
- バリデーションエラー、送信失敗、Firebase未設定時の案内に使うため。
- JavaScriptの遷移処理が何らかの理由で止まった場合のフォールバック表示を実装しやすくするため。

## 画面設計

### モバイル

- ヘッダー直下に完了メッセージを表示する。
- 見出しは1行または2行で自然に折り返す。
- CTAボタンは縦並びにし、横幅は既存の `.button--pill-large` に合わせて全幅にしすぎない。
- フッター直前SNS導線まで白く抜けないよう、`body` には既存の `site-end-page` を使う。

### デスクトップ

- 完了メッセージは中央寄せの読みやすい幅にする。
- セクション全体は既存の `section section--muted` を使い、ページ単体でも余白が不足しないようにする。
- CTAボタンは横並びまたは中央寄せで配置する。

## アクセシビリティ

- 完了ページのメイン見出しは `h1` とする。
- `main` にスキップリンクの遷移先 `id="main"` を置く。
- CTAはリンクとして実装し、ボタン風スタイルを適用する。
- 公式Instagramリンクは新規タブで開き、`rel="noopener"` を付与する。

## SEO / OGP

完了ページは送信後にだけ到達する補助ページのため、通常の集客対象にはしない。

方針:

- `title`、`description`、OGP、Twitter Card は既存ページと同じ形式で設定する。
- canonical は `https://molkkynist-a0abd.web.app/contact-complete.html` とする。
- 必要に応じて `meta name="robots" content="noindex"` を付与し、検索結果への露出を抑える。

## 影響範囲

変更対象候補:

- `contact-complete.html`
- `js/contact-form.js`
- `css/styles.css`
- `SITE_STRUCTURE.md`
- `CONTENT_GUIDELINES.md`
- 必要に応じて `README.md`

影響しないもの:

- Firestore `contactSubmissions` の保存仕様
- Cloud Functions の自動返信メール送信処理
- 管理画面のお問い合わせ管理
- プライバシーポリシー同意の必須チェック
- イベント日程の事前選択・トグル表示

## 実装手順

### Phase 1: 完了ページ作成

対象:

- `contact-complete.html`
- `css/styles.css`

実施内容:

- 既存公開ページと同じヘッダー・ナビゲーション・SNSフッター導線を持つ完了ページを作成する。
- 完了メッセージ、受付完了メール案内、返信目安、Instagram DM補足を配置する。
- 必要に応じて完了ページ専用の軽量CSSを追加する。

完了条件:

- `contact-complete.html` を単体で開いて完了ページとして成立している。
- モバイルとデスクトップでテキスト・ボタンがはみ出さない。

### Phase 2: 送信成功後の遷移実装

対象:

- `js/contact-form.js`

実施内容:

- `addDoc()` 成功後の `showStatus()` 成功表示を、`contact-complete.html` への遷移に変更する。
- 送信失敗時、バリデーションエラー、Firebase未設定時の挙動は維持する。

完了条件:

- Firestore 保存成功時のみ完了ページへ遷移する。
- 保存失敗時は現行どおりフォーム内にエラーが表示される。

### Phase 3: ドキュメント同期

対象:

- `SITE_STRUCTURE.md`
- `CONTENT_GUIDELINES.md`
- 必要に応じて `COMPLETED.md`

実施内容:

- 実装完了後、`SITE_STRUCTURE.md` に送信完了ページの位置づけを追記する。
- 完了ページ文言を `CONTENT_GUIDELINES.md` に必要最小限で追記する。
- 実装完了項目として `COMPLETED.md` に記録するか確認する。

完了条件:

- 実装内容とMarkdownの説明に矛盾がない。

## 検証方針

静的HTMLとして以下を確認する。

- `contact-complete.html` がブラウザで表示できる。
- モバイル幅で見出し・本文・ボタン・ヘッダーが重ならない。
- デスクトップ幅で余白と読み幅が過剰にならない。
- `contact.html` の送信成功時だけ `contact-complete.html` に遷移する。
- 送信失敗時は `contact.html` 内のエラー表示が維持される。
- 公式Instagram導線、トップページへの戻り導線が機能する。

## 受け入れ条件

- お問い合わせフォーム送信後、フォーム画面に留まらず `contact-complete.html` へ遷移する。
- 完了ページに「フォームの送信が完了しました」という趣旨が明確に表示される。
- 完了ページに受付完了メール送信の案内が表示される。
- 既存のお問い合わせ保存処理、自動返信メール処理、管理画面の一覧確認に影響がない。
- モバイル・デスクトップの両方で表示が破綻しない。
